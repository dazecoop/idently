Support

Idently is free and open source, maintained in the open on GitHub. The fastest way to get help, report a bug or ask for a feature is to open an issue.

Reporting a bug

Include as much of this as you can:

  • Your Firefox version, and Idently's version from about:addons.
  • What you did, what you expected, and what happened instead.
  • For a site rule that won't fire: the rule (Settings → Site rules → Export gives you a JSON file) and a description of the sign-in page. Leave out anything private.
  • A screenshot, if something looks wrong.

Never attach a session export made with Include cookies: it contains live logins.

Common questions

Does Idently replace Multi-Account Containers?

No, and you can keep using both. They share Firefox's containers, so Idently's sessions show up in Multi-Account Containers' list as containers named site - name. Multi-Account Containers is fine for a few long-lived containers. Idently is for many logins, such as fifteen accounts on one site: it names each session after the email you sign in with, groups sessions by site, and lets you search them.

Do I need Multi-Account Containers installed?

No. Containers are part of Firefox itself, and Idently uses them directly.

"New session tab" is greyed out.

Sessions are always started for the site in the current tab, so the button needs a normal web page open: not a new tab, about: page or Idently's own Settings. Open the site first, then click it.

Can I use Idently in a private window?

Not yet. Firefox doesn't offer containers in private windows, so sessions always open in a normal window.

A session says "logged out" but I'm still signed in.

That flag means the container has no cookies at all for the session's site. Some sites keep you signed in another way, such as local storage, or set their cookies on a different domain from the one the session was recorded under. Editing the session's domain to the one the site actually uses usually fixes it.

The same site shows up as two groups.

Sessions are grouped by the domain recorded when each was created, so account.example.com and example.com become two groups. Edit one session's domain to match the other and they merge.

My site rule never names the session.

Rules only run on tabs whose session has no name yet, and only on pages whose address matches the rule's domain (and path prefix, if set). Use Test on this page in the rule builder while the sign-in page is open: it shows what the selector reads, and whether that matches your value pattern. A pattern that rejects the value stops the rule firing, which is the point of it, so check it's not stricter than you meant.

The notch covers part of a site.

Hold Option (Alt) and drag it anywhere along the top edge; Idently remembers where you left it. The × hides it until the page reloads, and Settings can turn it off everywhere.

I reinstalled Idently and my sessions are gone.

Firefox keeps containers when an extension is removed, but the list that names them goes with the extension. Open Settings → Recover containers → Scan, check the domain on each one, and import them. Their logins come back with them.

Can I move my sessions to another computer?

Yes: Settings → Backup → Export, then Import on the other computer. Tick Include cookies to carry the logins across too, and treat that file like a password.

Is there a Chrome version?

No. Chrome has no equivalent of Firefox containers that an extension can use, so separate, isolated logins in ordinary tabs aren't possible there.
